# End-to-end test report — block C (2026-10-03)

Terminal Q4, one pass over the matrix in the day plan, run in a real browser (Playwright MCP tools, Chromium) against the real app: `ng serve` on :4200 proxying to the API on :5290, SQL Server seeded from `db/seed/`. Nothing was added to the repository to run it.

**How each case was judged.** Never by eye. For every URL, a script read the rendered page (cards, rows, statuses, ranges, order, verdict, notes, week picker) and fetched the API for the same parameters, then diffed the two field by field. The API was checked against hand-written SQL (`db/verify/verify-aggregates.sql`, which uses neither the dedup view nor the C# week boundaries) and, for one location, against the statistics computed by hand. Every case also checked the page text for `undefined`, `NaN` and `null`, the browser console for errors and warnings, and the network for failed requests.

**Baseline before the pass**: `dotnet test` 54/54, `ng test` 29/29, `ng build` clean.

## Findings

Classification follows the principle added at 22:20: a **code defect** is fixed and pinned by a test that fails without the fix; a **data condition** (missing, few or anomalous data) is neither changed nor hidden, and the screen says what is not shown and why, from what the API sends, with a test that checks the explanation appears. What to fix was decided by the planning session at 22:27 (`notes-q4.md`).
